# 真实城市：杭州（2026-11-11 起）

用户："整个世界太小了""如果能真实模仿城市就好了"→ 选杭州。

## 原则
- **骨架真实**：学校、地铁线路与站、小区、河、公园、商场、景点用 OpenStreetMap 真实位置（ODbL，署名 © OpenStreetMap contributors）。
- **细节补生成**：OSM 在国内日常小店很稀（紫金港 3km 内只登记 18 家饭馆），按真实密度在地铁站/小区周边补生成面馆、麻辣烫、菜市场、奶茶店等。构建时一次生成、写进 content，之后固定——像真城市一样不会每天变。
- **生活仍随机**：哪家好吃（隐藏品质）、今天想去哪、路上碰到什么，照旧按世界种子抽。
- **不调模型**：城市、路程、选店全是规则。

## 分步
- **C1 城市数据（已实现）**：`scripts/build_city.py` → `content/world/city/hangzhou.json`
  - 地铁：线路（去掉反向重复）、站坐标、换乘关系。
  - 她的生活圈（家、学校周边约 3km）：真实店 + 生成店；小区、河、公园。
  - 市区去处：西湖、湖滨、武林、河坊街、西溪湿地、运河、商场、影院、书店、博物馆。
  - 锚点：家（紫金港附近真实小区）、学校（浙大紫金港，文学院）、原有固定地点（楼下咖啡店、便利店、江边 → 真实/生成的对应地点）。
- **C2 接进世界（已实现）**：
  - 路程按坐标：近了走路，几公里骑共享单车，远了坐地铁（真实线路、站数、换乘），路上标"坐 3 号线"。
  - 去处按类别挑具体一家：远近、营业时间、价钱、印象（去过觉得好不好）、偶尔想试新的。地点用到才实体化。
  - 她只"知道"去过的地方和常经过的地方，城市地图是一点点走出来的。
- **C3 真实天气（已实现，见 world-events.md）**：Open-Meteo 杭州实况（晴/阴/雨/雪 + 温度），断网时退回随机天气。
- **C4 时间层次（已实现，见 world-events.md）**：工作日/周末、节假日、寒暑假（会不会回爸妈家）。
- 之后：钱、ddl（论文进度）、更多熟人。

## C1/C2 实现要点（2026-11-11）
- 家：紫金文苑（三坝站 440m）；学校：浙大紫金港（东门/西区/基础图书馆坐标）；10 个真实食堂/餐厅。
- 城市 503 个地点（OSM 175 + 补生成 328），地铁 297 站；市区有西湖、断桥、苏堤、白堤、灵隐寺、雷峰塔、河坊街、武林广场、湖滨银泰、西溪湿地、省博、晓风书屋等。
- `app/services/world/city.py`：坐标、`route()`（走路 75m/min、单车 220m/min+4、地铁按真实线路 Dijkstra，换乘 +5）、`nearby()`、营业时间、店用到才实体化。
- `life.py`：选项带 `venue` 的从城里挑具体一家——印象（隐藏品质 0.7 + 当天心情 0.3）+ 熟悉 + 一点好奇 + "昨天刚吃过换一家"；往返+最短时长超过空档就不起念头；正餐共用冷却（group meal 2.5h）。
- 她在这一片住了几年：第一次用到城市时，家 1.5km、学校 1km 内的日常店按距离大概率已知，好店去得多（`_venue_memory`）。
- 她知道：此刻在哪家店、路上怎么走（"在路上，坐2号线转1号线（三坝→龙翔桥）去…"）、住哪（situation 里一行），夜里回想"去了 xx（第一次去）"。
- 模板固定地点重启时改成城里真名：楼下咖啡店→政苑咖啡馆，便利店→全家，江边→东环河边。
- 模拟一周（4 个种子）：在外吃 ~半数正餐、有 2–3 家常去的、每周 ~1 家新店、奶茶 3–4 次、进城 0–1 次（周末加成待 C4）。
- 还没接：钱（价钱已记在 life.visit，未扣款）、冰箱吃不完、天气仍是随机（C3）、周末/节假日（C4）。
