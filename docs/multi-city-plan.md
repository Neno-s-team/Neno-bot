# 多城市规划（2026-11-12，草案）

> 这份只是规划，实现由主线会话来做。杭州是怎么做出来的见 `docs/city-plan.md`（C1–C4，已实现）；这里的阶段用 MC1–MC4，免得混。

**为什么要做**：最强的活人感是**她跟你在同一个城市**——你这边下雨，她那边也在下雨；你们能看同一场展览、同一部电影。
所以默认让她住在用户自己的城市（或者离得近的大城市）。

## 1. 现在哪些东西跟着杭州走

| 部分 | 现在 | 换城市要做什么 |
| --- | --- | --- |
| 地图 | `content/world/city/hangzhou.json`（120KB），由 `scripts/build_city.py` 从 OpenStreetMap 拉取 + 按真实密度补出小店 | 构建脚本里写死的锚点（家、学校的坐标，生活圈半径，市区范围）挪到每个城市一份的配置里 |
| 地铁 | 杭州地图里有真实线路和站，`city.route()` 按线路找最短路（走路 / 单车 / 地铁） | 大城市的 OSM 里都有地铁；没有地铁的城市要补公交或打车，`route()` 要有退路 |
| 学校里的地点 | 东门、西区、图书馆坐标，10 个真实食堂；模板里的固定地点换成城里真名（楼下咖啡店 → 政苑咖啡馆） | 每个城市包各配一套 |
| 天气 | Open-Meteo，按经纬度取（`weather.py`） | 已经通用，全球都能用 |
| 在映的电影 | 猫眼"正在热映"，全国一样 | 不用改 |
| 在追的剧 | 豆瓣热门，全国一样 | 不用改 |
| 展览和活动 | 豆瓣同城 `/location/{city}/`（`real.py`） | 换成对应城市的名字。小城市活动少，就用生成的兜底（已经有了） |
| 城里的事 | `content/world/events/hangzhou/city.json`（花期、杭州马拉松、老杭州照片……） | 拆成两份：全国通用的（节日、季节）放进公共文件，城市特色的每个城市写一份 |
| 地点映射 | `life.json` 里 `city.places`（`campus.east_gate` 这类锚点名） | 锚点名在各城市保持一样，坐标由每个城市的配置提供 |
| 她的身份 | 人设里写的是浙大研究生 | 角色卡那边的事；换了城市，学校或工作单位要跟着换 |
| 时区 | `MIND_TIMEZONE` | 国内不用动；海外城市要跟着换 |

代码里直接写"杭州"的地方很少（`build_city.py` 的锚点、`life.json` 里三处 `hangzhou`），大部分已经是读数据。

## 2. 怎么做

**城市包**：一个城市 = 地图 + 锚点 + 城市特色的事 + 豆瓣同城的城市名，放在 `content/world/city/<城市>/` 下面。

- **由我们离线构建，不在手机上现拉 OSM**：拉一整座城市的 OSM 数据又重又容易被限流，手机上做不稳。
  每个城市包压缩后大约一两百 KB，App 直接内置。
- **锚点**：每个城市挑一所大学和旁边一个住宅区（例如北京：海淀的一所高校和旁边的小区）。
  人设模板里的城市和学校写成变量，跟着城市包走（要跟角色卡那边对接）。
- **城市特色的事**：用模型按模板起初稿（"这座城市一年里固定会有的事：花期、马拉松、音乐节、本地节日"），人过一遍再入库。
- **只在第一次设置时选**：中途换城市等于她搬家了，世界里的地点会接不上。以后可以把"搬家"做成世界里的一件事，现在不做。

## 3. 分步

- **MC1 把写死的挪进配置**：一个 `city` 设置决定全部；杭州照常跑，行为不变。
- **MC2 先做 8 个城市包**：北京、上海、广州、深圳、成都、武汉、南京、西安，加上现有的杭州，共 9 个。
  先覆盖抖音观众最多的大城市，再按评论区里问得多的往上加。
- **MC3 第一次运行时选城市**：电脑版的 `run.py` 和手机第一次打开都问"她住在哪个城市"，默认用户所在的城市。
  人设里的城市和学校跟着变。
- **MC4 以后**：任意城市（手机上只拉家附近 3 公里的小范围地图）；海外城市（时区、本地的数据源、当地节假日）。

## 4. 要跟别的会话对接的

- **角色卡会话**：人设里的城市和学校要改成变量。
- **主线**：发布仓库的导出白名单要把城市包带上（`scripts/export_release.py`）。
