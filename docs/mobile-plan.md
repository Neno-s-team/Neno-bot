# 移动端与国内模型接入规划（2026-11-12，草案）

对外名「Meanwhile-此刻」；代码里照旧叫 Neno。

> 这份只是规划，在规划会话里写；APK 和代码实现由主线会话来做。

**一句话：安卓 App 自己就是完整的她。** 后端整个跑在手机里，用户只填一个 DeepSeek 密钥；不需要电脑，不需要翻墙，也不经过我们的服务器。

先做国内模型接入（电脑版、手机版都要用），再做移动端。

---

## 1. 国内模型接入

### 1.1 现状

- 大脑各层共用一个地址和一个密钥（`OPENROUTER_URL` / `OPENROUTER_API_KEY`），模型名是 OpenRouter 的写法（`deepseek/deepseek-v4.1-flash`）。
  世界另有一套 `WORLD_LLM_URL` / `WORLD_LLM_API_KEY`。
- 深思默认带 `{"reasoning": {"effort": "medium"}}`（`MIND_THINK_EXTRA_BODY`），这是 OpenRouter 的写法；DeepSeek 官方接口认不认，要验证。
- 所以现在做不到"深思走 DeepSeek 官方、措辞走 OpenRouter 上的 Gemini"。

DeepSeek 官方接口：地址 `https://api.deepseek.com`，OpenAI 兼容，支付宝和微信都能充值。
V4.1 Flash 的模型名是 `deepseek-flash`，V4 Pro 是 `deepseek-v4-pro`（2026-11-12 查的官方文档）。

### 1.2 档位

依据：`data/model-compare/run1/report.md`（廉价模型对比）和用户的结论。**L1 各档都用 V4.1 Flash。**

| 档位 | 给谁 | L2+L3 深思 | E2 措辞 | 要几个密钥 |
| --- | --- | --- | --- | --- |
| **国内（默认）** | 国内用户 | DeepSeek V4 Pro | DeepSeek V4 Pro | 1 个 DeepSeek |
| 国内 + Gemini 措辞（可选） | 能连上 OpenRouter 的 | DeepSeek V4 Pro | Gemini 3.8 Flash | DeepSeek + OpenRouter |
| 境外（可选） | 海外用户 | DeepSeek V4 Pro | Gemini 3.8 Flash | 1 个 OpenRouter |
| 高配（可选） | 不在乎钱 | Claude Opus 5.5 | Gemini 4 Carbon | 1 个 OpenRouter |

其余各项（世界里的 NPC、上网、L4 睡前回想、摘要、看图）各档都用 V4.1 Flash：它原生支持图片，也最便宜。

**国内档的措辞为什么用 V4 Pro**：措辞最好的是 Gemini 3.8 Flash（10 条里条数全对、没有超长、每条平均 8.7 字）。
国内的候选里，V4 Pro 整条链跑下来条数对了 6/10、超长 3/15、每条 9.5 字，不如 Gemini 但能用；
GLM-5.3 条数更准（8/9），但超长更多，还要第二个密钥。选 V4 Pro 是为了只要一个密钥。

**已知问题**：对比里 L4 用 DeepSeek（Flash 和 Pro 都有）会引用不存在的记录，检查环节抓到了。要确认这类引用会被丢掉，不会写进记忆。

### 1.3 慢和钱

- **慢**：V4 Pro 做深思平均要 61.6 秒（对比报告）。她本来就不秒回，多数时候能盖住；
  但她正闲着、跟你一来一回聊的时候，一条要一分多钟。上线前要在真聊天里测；太慢的话，"快聊"的时候改走 Flash。
- **钱**：按报告里的价格，一条走完深思的回复大约 6–7 分钱人民币，不走深思的不到 1 分。
  DeepSeek 官方价格跟 OpenRouter 不一样，高峰时段还有加价，以官方价格页为准。

### 1.4 要改的代码

1. **加"提供方"**：`deepseek`、`openrouter`、`custom`（任何 OpenAI 兼容的地址），每个提供方有自己的地址和密钥。
2. **每层的模型写成"提供方:模型名"**，例如 `deepseek:deepseek-v4-pro`、`openrouter:google/gemini-3.8-flash`。
   不写提供方的，照旧走 OpenRouter，老配置不受影响。
3. **档位就是一组预设**：`.env` 里只写 `MODEL_PRESET=cn` 和密钥就行；想细调，再一层一层覆盖。
4. **额外参数按提供方转换**：OpenRouter 的 `reasoning.effort`，到 DeepSeek 那边换成它自己的写法，或者去掉。
5. **用量统计按提供方记**：DeepSeek 返回的缓存命中字段名不一样。
6. **`run.py` 第一次运行时**，先问用 DeepSeek 还是 OpenRouter，再要对应的密钥，然后发一次测试请求，确认能用。

**协调**：`run.py` 和 `app/config.py` 正是部署主线那个对话在改的地方（`app/config.py` 现在有它没提交的改动）。
这一块要么交给它做，要么等它提交以后再接手，不能两边同时改。

## 2. 移动端

### 2.1 走哪条路

| | A：手机里跑完整后端 | B：手机连你电脑上的后端 |
| --- | --- | --- |
| 用户要做的 | 装 APK，填密钥 | 先在电脑上部署，再配内网穿透 |
| 她的日子 | 在手机里过 | 电脑开着才过 |
| 国内能不能用 | 能 | 穿透要靠 cloudflared 之类，国内不稳 |
| 工作量 | 大 | 小（以前做过：基于 Operit 改的安卓壳，后来删了） |
| 适合谁 | 抖音来的普通用户 | 已经在电脑上跑起来的人 |

**选 A。** B 解决不了"方便用户自己接 API"这件事。

### 2.2 A 怎么做

- **外壳**：Kotlin + Jetpack Compose，原生安卓。只做安卓。
- **后端**：用 Chaquopy 把现在的 Python 后端原样打包进 App，在前台服务里启动 uvicorn，只监听 `127.0.0.1`。
  后端代码不分叉，电脑版和手机版是同一份。
- **界面怎么跟后端说话**：App 就是第三个"通道"，跟 `channels/terminal.py`、`channels/telegram_bot.py` 一样走本机 HTTP：
  发消息进去，取到该发的消息，显示出来，回执。后端不用为手机改协议。
- **她的消息怎么送到**：前台服务常驻一条"她的世界在运转"的通知；她发来消息时，手机弹通知。
- **被系统杀掉怎么办**：世界引擎本来就支持停机后按真实经过的时间有界补算（`docs/world-engine-plan.md`），
  下次打开时会补上。她的主动消息会晚一点到，这跟"不秒回"的设定不冲突。
  国产系统要引导用户把 App 加进电池白名单。
- **数据**：全都在手机里；提供导出和导入，用来换手机、做备份。

### 2.3 风险：先花一周验证

现在的依赖里，原生的只有 `pydantic`（底下的 pydantic-core 是 Rust 写的）和 `Pillow`，其余都是纯 Python。要验证：

1. pydantic-core 在 Chaquopy 上有没有现成的包；没有就自己交叉编译。
2. 打包进去的 SQLite 带不带 FTS5（记忆检索要用）。
3. 前台服务常驻一天，耗多少电、占多少内存。
4. 被杀掉再打开，补算对不对，主动消息会不会丢。
5. `uvicorn[standard]` 里的原生加速包在手机上不装，换成纯 Python 版的 uvicorn。

有过不去的，就退到 B。

### 2.4 分步

- **M0 验证（约 1 周）**：一个最小的 APK，把后端跑起来，打通"发一条 → 她回"，把上面 5 条测完。过关才往下做。
- **M1 能用**：聊天界面（拆条、正在输入、已读、她在干嘛、大概多久后能看到）；
  第一次打开填 DeepSeek 密钥 → 测试一次 → 进入；通知；APK 放到 GitHub Release。
- **M2 像样**：可选档位（Gemini 措辞、境外、高配）；数据导出导入；电池白名单引导；"她的一天"（只看）；
  她用 WebView 上网（N2，见 2.5，验证过了再开）。M1 就带着不开浏览器的上网（N1）。
- **以后**：发图片、语音。

### 2.5 她在手机上怎么上网

电脑上现在有两种上网方式（`docs/world-events.md` 的 N1、N2）：

- **N1 不开浏览器**：直接读网页文字（知乎日报、少数派、澎湃热榜、B站热门，搜索用 360）。纯 Python，一回大约调用 6 次便宜模型。
- **N2 真浏览器**：Chrome + agent-browser，开在隐藏的桌面上，登录她自己的 X、小红书、Reddit。开着的时候占 400MB 到 1.2GB 内存。

手机上：

| | 怎么做 | 默认 |
| --- | --- | --- |
| N1 | 原样搬过去，不用改 | 开 |
| N2 | 不装 Chrome，也不用 agent-browser：用手机自带的 WebView（每台安卓都有，Chromium 内核） | 可选；用户在"她的手机"页里替她登录账号以后才开 |
| 不做 | 操控用户手机上真的小红书、抖音 App（会抢用户的屏幕，用的也是用户自己的号）；云端浏览器（要我们自己架服务器） | — |

**N2 手机版怎么做**：

- **接口不变**：`surf.py` 只用到 `browser` 模块的 `available` / `open` / `snapshot` / `click` / `scroll` / `back`，外加 `condense`。
  在手机上实现一个接口相同的 WebView 版（Chaquopy 可以直接调用 Java/Kotlin），`surf.py` 不用改。
- **快照**：往页面里注入一段 JS，给页面文字和能点的东西编上号，输出成跟 `condense` 处理后一样的格式。
- **只在连着 Wi-Fi 时开**；不加载图片（她本来就只读文字），省流量也省内存；用完马上销毁，跟电脑上"用时才开"一样。
- **登录**：App 里有一个"她的手机"页，打开同一个 WebView，用户在里面替她注册、登录专属账号（相当于电脑上的 `scripts/open-neno-browser.ps1`）。

**要先验证的**（M0 之后单独做一轮）：

1. WebView 不显示在屏幕上（在后台服务里）的时候，信息流还会不会往下加载——有的网站看不见就不加载。
2. X 在 WebView 里能不能登录。Google 不允许在内嵌 WebView 里登录 Google 账号，所以 Gmail 这类走不通。
3. 小红书的手机网页版大多逼你下载 App，能看的内容很少。要不要用"桌面版网站"（像手机 Chrome 里"请求桌面版网站"那样）？
   这样会改 UA，跟"不伪装浏览器身份"那条线有点冲突，到时候要用户来定。
4. 开着的时候在手机上占多少内存。

**结论**：先做 N1（M1 就有），N2 放到 M2 以后，验证过了再开。大多数用户不会替她注册账号，N1 就是他们看到的"她自己上网"。

### 2.6 体验要点（给主线做界面时用）

**像在跟一个人发消息，不像在用 AI 工具**
- 没有"新对话"、"重新生成"、模型选择；设置藏到二级页里。
- 她的消息一条一条来：正在输入… → 一条 → 停一下 → 下一条（E3 已经算好了拆条和时间）。
- "已读"要等她真看到才显示（L0 判断她看到手机的那一刻），没看到就一直是未读——这是整个产品最核心的机制，要让人一眼看见。
- 名字下面一行小字写她的状态："在上课"、"刚刚在线"、"睡着了"。点一下才显示"大概 40 分钟后会看手机"，平时不露出机制。
- 你连发几条、或者中途补一句，都不用等她，输入框永远能发。
- 界面干净，不仿微信。

**通知像真人发来的**
- 标题是她的名字，内容就是消息原文；几条合成一组；能在通知里直接回复。
- 前台服务那条常驻通知放进一个静音、低优先级的通知渠道，写"她的世界在运转"，用户可以在系统里把它折叠起来。

**打开就有东西，不转圈**
- 先显示本机存着的消息和她此刻在干嘛；如果 Python 后端被杀了要重启，就在后台慢慢起，这期间发的消息先排队。
- 聊天页空着的时候，显示她现在在哪、在干嘛，不要一片空白。

**第一次打开，一分钟内聊上**
- 选档位（默认国内）→ 粘贴密钥（附教程：去哪申请、充多少；充 10 块钱能用很久）→ 自动测试一次 → 进入。
- 第一次见面怎么开场，交给角色卡那边定。

**花了多少钱看得见**
- 设置里写"今天花了 ¥0.42"（用量统计已经有了）。用户自己出钱，透明最重要。

**以后**
- "她的一天"页签（只看）：今天去了哪、干了什么、刷到了什么、日记。也是拍视频的素材来源。
- 表情包（Telegram 那边已经有她的表情包）、深色模式、字体跟随系统。

实现的时候可以用 `impeccable` / `ui-ux-pro-max` 这两个技能来打磨界面。

### 2.7 不做

- 不架服务器，不做账号体系，不替用户存聊天。
- 不上国内应用商店，安装包只放 GitHub Release。
- 先不做 iOS（不能装 APK 这类安装包，后台限制也更严）。
